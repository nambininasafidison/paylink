### Added

- **The v2 web app, `apps/web`** ([README](apps/web/README.md), [ADR 0014](docs/adr/0014-web-app-and-single-pages-site.md)): a Vite 8.3.2 multi-page PWA in strict TypeScript 6.0.3, no UI framework, in v1's Precision Terminal language (dark display windows, LED lamps, printed card and receipt slip, ledger tape), mobile first, light and dark, EN/FR/MG. Routes `/` (sign an EIP-712 invoice in the wallet after a signing display; share by link, QR code, WhatsApp, share sheet, A6 print, till), `/pay/` (four lamps from the chain: signature, network, genuine contract, still payable; any red lamp locks Pay; `payWithPermit` or exact-amount approve then `pay` with registry-clamped gas limits; receipt verified before "Approved"), `/r/` (receipt re-verified on every opening, 80 mm and A6 print), `/ledger/` (device store merged with `statesOf` and chain time, tally, filters, RFC 4180 CSV with CAIP ids, cancel), `/send/` (address book of receive cards), `/till/` (armed or watching, `eth_getLogs` from `head − 10`), `/status/` (each chain checked live), `404.html`. Edition extension points for the account layer (EIP-6963 with EIP-3326/3085 today), the default token and the payment rail (the payer's wallet today); runtime `/config.json` validated with zod, addresses from the registry only; IndexedDB device store with re-validation on read and a memory fallback; read model chain > device > indexer; strict CSP with Trusted Types (`paylink-sw`), frame lock, closed Permissions-Policy; service worker with an update prompt. 195 unit tests (Vitest, happy-dom); `e2e/specs/app.spec.ts` (12 Playwright specs on anvil under the production headers, axe in light and dark at 1280 and 390 px).
- **One Cloudflare Pages site** ([runbook](docs/runbooks/cloudflare-pages.md)): `bash apps/web/scripts/cloudflare-pages.sh` installs the web app from the frozen lockfile and builds the editions `all` (at `/`), `monad` and `base`, copies the frozen v1 app to `/arc/` byte for byte and the deploy kit to `/deploy/` (and `/v2/deploy/`), and writes `_headers` with one Content-Security-Policy per area (detach, then set). Gates: `_headers` up to date, the pay route within 110 kB of gzipped JavaScript (92.6 kB), no source maps, no end-to-end hook in production. Verified from a clean clone with an empty pnpm store.
- **`@paylink/design`** ([README](packages/design/README.md)): v1's tokens byte for byte, the components in cascade layers, the OFL fonts, contrast, palette and layer tests. **`@paylink/i18n`** ([README](packages/i18n/README.md)): EN, FR and MG with typed keys and placeholders, plurals, `Intl` formatting and a completeness gate that covers every SDK error key; the Malagasy drafts are listed for the founder's review.

- **Gasless relayer, `apps/relayer`** (PAYLINK-V2-SPEC §3.7, [ADR 0007](docs/adr/0007-relayer-durable-object-per-chain.md) amended, [README](apps/relayer/README.md), [runbook](docs/runbooks/relayer.md)): a Cloudflare Worker (Hono 4.13.13, zod 4.6.5, viem 2.57.3) with one Durable Object `ChainSender` per chain. `POST /v1/{chainId}/pay` relays `payWithAuthorization` and `POST /v1/{chainId}/cancel` relays `cancelBySig` on Monad testnet, Base Sepolia and Arbitrum Sepolia; `POST /v1/10143/onboard` asks Monad testnet's AUSD faucet for a payer; `GET /v1/health` reports each chain. Every request passes zod schemas equal to the invoice spec's JSON Schema, the SDK's relay checks (both signatures with the contract's and the token's dispatch, the recomputed binding nonce, the 120 s relay margin), a one-cent minimum, rate limits per IPv4 address or IPv6 /64, daily caps and `RelayAdmissionLedger`, then `eth_call` at the checked block and again on the pending block. Gas limits are `clamp(estimate × 1.10, floor, ceiling)` from `@paylink/chains` (an estimate above the ceiling is refused); the Durable Object owns the nonce, the send queue, replacement (same nonce, fees × 1.25 after 30 s) and voiding of stuck nonces, revert attribution and the daily gas budget. One signing choke point: value 0, testnets only, two PayLinkV2 selectors, the faucet's `requestFunds(address)` or a self-void. CORS only for `https://paylink-mg.pages.dev` and its previews; RFC 9457 problem responses with a `fallback`; JSON logs without keys, bodies, signatures or IP addresses. `RELAYER_PK` comes only from the Worker secret. Cloudflare's Git integration deploys the committed, reproducible bundle `apps/relayer/deploy/worker.js` byte for byte; a Node adapter serves the same app and engine against anvil for e2e and demos. Tests: unit (Hono `app.request()`), anvil with the release build and Mock3009 (a real relayed payment, tampered amount, reference and invoice, replays, gas clamp at the floor and the ceiling, attribution and bans, a superseding self-submission), fault injection, the bundle in workerd under `wrangler dev`, and an opt-in run on a Monad testnet fork with the real AUSD and faucet.

### Security (pre-freeze audit, 2026-10-07)

- **Retries can no longer pay twice.** The invoice spec told payer clients to re-sign every attempt with a fresh `payerSalt`, and the router offered permit and approve-and-pay after a slow relay; on receive cards, open-amount tills and N-seat links a late relay then settled a second payment. New spec §8.6 makes a retry resubmit the same signed authorisation and allows a new signature or another path only once the old one is cancelled on the token or expired. `@paylink/sdk` adds the outstanding-authorisation record, assessment, resubmission and `cancelAuthorization` helpers; `authorizePayment` now requires the assessment (**breaking** for SDK callers: pass `outstanding: null` for a first payment) and the router resubmits only. `IPayLinkV2` NatSpec corrected; contract behaviour unchanged, but the release `initCodeHash` is now `0x289dcd64…7ac5` (metadata only).
- **Relayer griefing bounded.** A payee (with or without code) or a payer (EIP-7702) can make a simulated relay revert on inclusion at the relayer's expense. `RelayAdmissionLedger` bounds relays in flight per key, payee, payer and token, bans after a post-simulation revert, and applies a code policy; `checkRelayPayRequest` verifies the payer with FiatToken's dispatch and reports both accounts' code; payers with code route as smart accounts. Spec §8.3 and §13.3, THREAT_MODEL T-03, T-13 (corrected), T-45 and T-46, ADR 0007 amended.
- **Test gaps closed.** The invariant campaign gains a forward-leg fee token and `reconfigureFee`, so it alone kills mutants of the EIP-3009 conservation post-check and forward-leg payee check; error precedence is pinned for every pair of checks on every path and fuzzed over any subset; the `payments` counter bound and falling balances are tested.
- **Gates and claims.** The gas gate is documented as `pnpm run snapshot:check`; Node ≥ 22.18 is required (the packages' scripts run TypeScript directly); CI enforcement claims are marked planned until `.github/workflows` lands; the threat model marks evidence that is not built yet, and `check-docs.py` checks cited paths and the markers; the ESLint DOM-sink ban covers computed, object-literal, `Reflect`, `setAttribute` and HTML-parsing-method forms, with tests.

### Security (re-audit, 2026-10-07)

- **Relay time bounds keep a margin; bans follow the cause (A-04).** A time bound one second ahead of the simulated block (a payer-chosen `validBefore`, an invoice's last second, a cancellation with `deadline = now`) passed every relayer check and `eth_call`, then reverted on inclusion with no attacker transaction, and every such revert banned the key, the payee and the payer together, so a sybil payer could shut an honest merchant out of the gasless path for a day. Every v2 chain now carries a relay margin (`relay.minRemainingSeconds`, 120 s, in `@paylink/chains`), applied by `checkRelayPayRequest` and `checkRelayCancelRequest` (which now require `now`), again at admission and before broadcast (`assertRelayWindow`). `attributeRelayRevert` attributes a post-simulation revert from chain evidence (superseded, late inclusion, payer, payee, sold out, token, unattributed), and `RelayAdmissionLedger.release` applies `REVERT_PENALTIES`: a payer-side failure never bans the payee, and the same authorisation landing first elsewhere bans nobody. Requesters are identified per IPv4 address or IPv6 /64 (`requesterFromIp`) and limited to 20 relays an hour. Ledger snapshots move to version 2. Spec §13.2, §13.3, §14.11, §14.12; THREAT_MODEL 1.3 (T-03, T-13, T-26, T-34); ADR 0007 amended.
- **Checks-effects-interactions pinned on every settlement path.** Read-only re-entry tests now cover `payNative` (the payee's own `receive`, `PeekingPayee` mock) and `payWithAuthorization`; mutants M46–M49 (link-state write deferred past the interaction, one per path) are in the mutation catalogue and all killed. No contract change.
- **ADR 0003 amended** to the revised retry rule (`payerSalt` once per intended payment; a retry resubmits the same authorisation), and `check-docs.py` gains a `stale` check that fails when a superseded rule reappears as normative text.

### Security (test-quality review, 2026-10-07)

- **Exactness tested in both directions.** I1 (PayLink's balance unchanged across a call) and I6 (payee credited exactly `amount`) are equalities, but every mock only made balances fall short, so turning any exactness check from `!=` into `<` passed every gate. New `OverCreditToken` mock, unit tests that pin the documented errors one unit *over* the amount on every check, and a `reconfigureOverCredit` campaign action; mutants M50–M54 are killed by the unit suites and by the CI campaign alone. No contract change.
- **`tx.origin` never authorizes (SWC-115).** Unit tests separate `msg.sender` from `tx.origin` on `cancel`, `cancelBySig` and the payer of every path, including a lure contract that a payee or a payer with a standing allowance is tricked into calling; the campaign seeds the origin; mutants M55–M59 killed. No contract change.
- **Coverage gate works on a clean checkout.** `ReleaseGraph.t.sol` skips itself under `forge coverage` (which never writes `out/`) and refuses a stale artifact, so the `Bytes.sol` and import-graph checks can no longer fail on a fresh CI job or pass on an old build.
- **Halmos, Echidna and Medusa harnesses delivered.** `protocol/test/symbolic/` (Halmos: conservation over arbitrary token behaviour, and the payment and cancel state machines), `protocol/test/properties/` (one property contract for I1–I11 shared by Echidna and Medusa, with a forge test that keeps it live) and pinned tool versions; first runs and mutant runs in `protocol/audit/properties.md`. The self-review and the threat model no longer claim evidence that did not exist (Echidna, Medusa, Halmos, Aderyn, CodeQL, `fork-nightly.yml`); the nightly workflow stays planned.

### Changed

- **Monad testnet 10143 is live in the registry.** PayLinkV2 2.0.0 at `0x448eCce9711860502806A3d5B021a4f9Ba715082` (CREATE2, block 69331735, [record](protocol/deployments/10143.json), re-verified on-chain with `tools/verify-deployment`) is now generated into `@paylink/chains` and the deploy kit's `data/chains.json`, so the apps can pay on it and the deploy page only verifies it; the relayer bundle is rebuilt with it (Monad leaves `awaiting-deployment`). The relayer is deployed by Cloudflare's Git integration from `apps/relayer/deploy/`, not by a `relayer.yml` workflow with a Cloudflare API token in GitHub; the spec's fallback transfer from a relayer-held AUSD inventory is not built, so the relayer never signs a token transfer. ADR 0007, ARCHITECTURE §3 and §4.8, the deploy, faucets and demo runbooks, the incident-response levers and THREAT_MODEL T-33 and T-38 now say so; T-47 (relayer code substitution or key exposure) and T-48 (cross-origin use) are new, and the relayer's evidence cites its test files.
