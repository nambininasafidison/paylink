# Runbook: one Cloudflare Pages project for the whole site

How the Pages project **`paylink-mg`** builds and serves PayLink from this repository at **`https://paylink-mg.pages.dev`**: the v2 app and its editions, the frozen v1 app and the browser deploy kit, from one build output folder. The decision is [ADR 0014](../adr/0014-web-app-and-single-pages-site.md); the app itself is described in the [web app README](../../apps/web/README.md).

Who does what:

| Step | Who | Where |
|---|---|---|
| Code, the build script, `_headers`, the checks below | Claude | this repository |
| Push `main` | you | GitHub |
| Change the build settings once ([§3](#3-change-the-build-settings)) | you, or your browser assistant with the [prompt in §8](#8-prompt-for-your-browser-assistant) | Cloudflare dashboard |
| Check the live site ([§5](#5-check-the-live-site)) | you, the assistant, or Claude (`paylink-mg.pages.dev` is reachable from the sandbox when the proxy allows it) | browser or shell |

Nothing in this runbook involves a key, a secret or a wallet signature.

## 1. What the site serves

One build writes one folder, `apps/web/dist`, that holds everything:

| Path | What | Source | Content-Security-Policy |
|---|---|---|---|
| `/`, `/pay/`, `/r/`, `/ledger/`, `/send/`, `/till/`, `/status/` | the v2 app, edition `all` (Monad testnet, Base Sepolia, Arbitrum Sepolia; injected wallets) | `apps/web` | the app's: `script-src 'self'`, `style-src 'self'`, Trusted Types (`paylink-sw`), `connect-src` = the registry RPCs and `/config.json` endpoints, `frame-ancestors 'none'` |
| `/monad/…`, `/base/…` | the same routes for the Monad and Base editions ([ADR 0008](../adr/0008-editions.md)) | `apps/web` built with `VITE_EDITION` | the app's |
| `/arc/` | the frozen v1 app (Arc mainnet), **byte for byte** | `web/` without `web/v2/` and `web/_headers` | v1's own: its scripts plus the SHA-256 of `deploy.html`'s inline script, inline styles, `connect-src` = Arc mainnet's RPC |
| `/deploy/` and `/v2/deploy/` | the browser deploy kit ([ADR 0013](../adr/0013-browser-deploy-page.md)), at its new and its first URL | `web/v2/deploy/` (only the two links to v1's stylesheet and fonts point at `/arc/`) | the kit's own meta policy, plus `frame-ancestors 'none'` |
| `/config.json` | runtime configuration (banner, relayer, indexer, preferred RPCs), never cached | `apps/web/public/config.json` | — |
| `/_headers` | every header above | generated by `apps/web/scripts/site.ts`, committed as `apps/web/public/_headers` | — |

Every area also gets `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Resource-Policy: same-origin`, HSTS and a `Permissions-Policy` that turns everything off except fullscreen, screen wake lock (till) and passkeys. Cloudflare applies every matching `_headers` rule and joins a header set twice with a comma, which would intersect two policies; each area's rule therefore first removes the app's policy with the documented detach line `! Content-Security-Policy` (**C**, Cloudflare Pages docs, "Detach a header").

## 2. Build settings

| Setting (Workers & Pages → `paylink-mg` → Settings → Build) | Value today | New value |
|---|---|---|
| Production branch | `main` | `main` (unchanged) |
| Framework preset | None | None (unchanged) |
| Build command | *(empty)* | `bash apps/web/scripts/cloudflare-pages.sh` |
| Build output directory | *(empty)* | `apps/web/dist` |
| Root directory (advanced) | `web` | *(empty: the repository root)* |
| Build system version | as set | **v3** (the latest) |
| Build watch paths | default (`*`) | default (`*`) |

Environment variables, type **Text**, for **Production** (and Preview, should previews ever be turned on):

| Variable | Value | Why |
|---|---|---|
| `NODE_VERSION` | `22.22.0` | The build needs Node ≥ 22.18 (TypeScript type stripping); the v3 image defaults to 22.16.0 (**C**, cloudflare-docs `pages-build-environment/v3.yaml`, 2026-10-08). `.nvmrc` says the same, and the variable makes it explicit |
| `PNPM_VERSION` | `10.28.0` | The workspace's pinned pnpm; the v3 image does not read the version from `pnpm-lock.yaml` and defaults to 10.11.1 (**C**, same source) |
| `SKIP_DEPENDENCY_INSTALL` | `1` | Stops Pages from installing dependencies by itself before the build command (**C**, "Skip dependency install"): the repository root also holds the frozen v1 app's `package-lock.json`, which the v2 site must not install. The build command installs exactly what it needs |

Branch control (Settings → Build → Branch control):

- **Production branch:** `main`, automatic deployments on.
- **Preview branch:** **None**. A preview at `<branch>.paylink-mg.pages.dev` is a subdomain of the passkey rpId `paylink-mg.pages.dev` and could ask for its passkeys ([ADR 0005](../adr/0005-dedicated-origin-and-rpid.md), threat T-05). The relayer's CORS list also names the production origin.

What the build command does (`apps/web/scripts/cloudflare-pages.sh`, about 15 s in the sandbox with an empty store):

1. checks Node ≥ 22.18 and picks pnpm 10.28.0 (the one on `PATH`, else Corepack, else `npx pnpm@10.28.0`);
2. `pnpm install --frozen-lockfile --filter "@paylink/web..."`: the web app and the workspace packages it uses, exactly as `pnpm-lock.yaml` pins them (no Foundry, relayer or browsers);
3. `pnpm --filter @paylink/web run build`: three Vite builds (`all` at the root, `monad`, `base`), then the assembly (`/arc/`, `/deploy/`, `/v2/deploy/`, `_headers`) and the gates: `public/_headers` up to date, the pay route within **110 kB of gzipped JavaScript** (spec §4.4; 92.6 kB on 2026-10-08), no source map, no end-to-end hook in a production bundle;
4. checks that `index.html`, `_headers`, `arc/index.html` and `deploy/index.html` exist.

Limits, for reference (**C**, Cloudflare Pages docs): 100 `_headers` rules (we use 11) and 2,000 characters per line (longest: 435); 20,000 files per site on the Free plan (we ship 167); 25 MiB per file.

## 3. Change the build settings

Do this once, **after** `main` contains `apps/web/scripts/cloudflare-pages.sh` (Claude tells you when it is pushed). Dashboard labels move from time to time; the text in quotes is what to look for.

1. Open `https://dash.cloudflare.com`, sign in, pick the account.
2. Left sidebar: **"Workers & Pages"** (under "Compute"). Open the project **`paylink-mg`**.
3. Tab **"Settings"** → section **"Build"** (or "Builds & deployments") → **"Build configuration"** → **"Edit"**:
   - "Framework preset": **None**.
   - "Build command": `bash apps/web/scripts/cloudflare-pages.sh`
   - "Build output directory": `apps/web/dist`
   - "Root directory (advanced)": **clear the field** (it says `web` today). Empty means the repository root.
   - **"Save"**.
4. Same page, **"Build system version"**: if it is not v3, choose **v3** and save.
5. **"Variables and Secrets"** (Settings → "Environment variables" on older layouts), environment **Production**: **"Add"** three variables of type **Text**: `NODE_VERSION` = `22.22.0`, `PNPM_VERSION` = `10.28.0`, `SKIP_DEPENDENCY_INSTALL` = `1`. **"Save"**.
6. **"Branch control"**: production branch `main`, "Enable automatic production branch deployments" ticked; "Preview branch": **None**. **"Save"**.
7. Tab **"Deployments"**: on the latest production deployment, open the **"…"** menu → **"Retry deployment"** (or push any commit to `main`).
8. Open the new deployment's **build log**. It must end with `Cloudflare Pages output: apps/web/dist`, then "Success: Your site was deployed". Then run [§5](#5-check-the-live-site).

## 5. Check the live site

From a shell (the sandbox, or any computer):

```bash
SITE=https://paylink-mg.pages.dev
for path in / /pay/ /r/ /ledger/ /send/ /till/ /status/ /monad/ /base/ /arc/ /deploy/ /v2/deploy/ /config.json /sw.js; do
  printf '%-14s %s\n' "$path" "$(curl -s -o /dev/null -w '%{http_code}' "$SITE$path")"
done                                                  # every line 200
curl -sI "$SITE/" | grep -i '^content-security-policy' | grep -c "trusted-types paylink-sw"   # 1
curl -sI "$SITE/arc/" | grep -i '^content-security-policy' | grep -c 'rpc.mainnet.arc.io'     # 1
curl -sI "$SITE/deploy/" | grep -ci '^content-security-policy'                                # 1 (one policy, not two)
curl -s "$SITE/arc/" | cmp - web/index.html && echo "v1 byte for byte"                        # from a checkout of main
curl -s -o /dev/null -w '%{http_code}\n' "$SITE/no-such-page/"                                 # 404
```

In a browser:

- [ ] `/` shows the terminal ("Sign a link. Get paid in dollars."), `/status/` lights one row per network: "Network answers" green for each, "Genuine contract" green once PayLinkV2 is deployed on that chain (amber "not deployed" before).
- [ ] The language dial switches EN → FR → MG; the theme dial switches light and dark.
- [ ] `/arc/` is the v1 app as it was at `/`; `/deploy/` shows the release identity (`initCodeHash` `0x289dcd64…7ac5`).
- [ ] DevTools → Console on `/`: no "Refused to …" CSP message. Application → Service workers: `sw.js` activated for scope `/`.

## 6. Runtime configuration and headers

`/config.json` holds what may change without a rebuild of the code: an incident banner, the relayer and indexer endpoints, preferred RPCs. It never holds an address. Every endpoint in it must also be in the app's `connect-src`, so changing it is a commit, never a dashboard edit:

1. Edit `apps/web/public/config.json` (the schema is `apps/web/src/core/config.ts`; an invalid file is ignored in favour of the defaults, and `/status/` says so).
2. `pnpm --filter @paylink/web run headers` regenerates `apps/web/public/_headers` with the new origins. The build refuses a stale `_headers`, and `apps/web/test/site.test.ts` checks the policies.
3. Commit both, push `main`; Pages deploys in about a minute. `config.json` is served with `Cache-Control: no-cache` and the service worker never caches it.

For example, turning the relayer on ([relayer runbook §7](relayer.md#7-turn-the-relayer-on-in-the-app)) sets `"relayer": { "url": "https://paylink-relayer.raherizonambinina.workers.dev", "chains": [10143, 84532, 421614] }` and adds that origin to `connect-src`.

The incident banner ([incident response](../security/incident-response.md)) is the same kind of commit: `"banner": { "level": "critical", "text": { "en": "…", "fr": "…", "mg": "…" } }`.

## 7. Roll back

- **A bad deployment:** Deployments → pick the last good production deployment → "…" → **"Rollback to this deployment"**. Instant; no build.
- **Back to the old layout** (v1 at `/`, the kit at `/v2/deploy/`): set the build command and output directory back to empty, the root directory back to `web`, and retry the deployment. The repository needs no change: `web/` and `web/_headers` are as they were.

## 9. Reproduce a Pages build locally

The build command is the whole build, so a clean clone reproduces it exactly:

```bash
git clone https://github.com/nambininasafidison/paylink.git && cd paylink
bash apps/web/scripts/cloudflare-pages.sh       # Node >= 22.18; uses pnpm 10.28.0 however it can
ls apps/web/dist                                # the folder Pages uploads
```

**Verified 2026-10-08** in the sandbox, from a fresh `git clone` of the commit that added this runbook, with an empty pnpm store (every package downloaded from the npm registry): 13 s in all (install 5.3 s), 167 files, `/pay/` 92.6 kB of gzipped JavaScript in each edition, `apps/web/dist/arc/` identical to `web/` (`diff -r`, apart from `web/v2/` and `web/_headers`, which are not v1). In the same clone, a full `pnpm install --frozen-lockfile` and the web app's, design system's and translations' typecheck, lint and tests pass.

The end-to-end suite serves the same build with a Pages-compatible server (`e2e/fixtures/pages.ts`: the routing, the nearest `404.html`, `_headers` with detach and comma-joining) and runs the app under its production headers: `pnpm --filter @paylink/e2e test` ([e2e README](../../e2e/README.md)).

## 10. Troubleshooting

| Build log says | Cause | Fix |
|---|---|---|
| `Node 22.16.0 is too old` | `NODE_VERSION` missing and the image default used | Add `NODE_VERSION` = `22.22.0` ([§2](#2-build-settings)) |
| `ERR_PNPM_OUTDATED_LOCKFILE` / `frozen-lockfile` | a `package.json` changed without `pnpm-lock.yaml` | Claude runs `pnpm install` and commits the lockfile; never turn `--frozen-lockfile` off |
| `apps/web/public/_headers is stale` | `config.json`, the registry RPCs, v1's inline script or the kit's policy changed | `pnpm --filter @paylink/web run headers`, commit |
| `the pay route of edition … is over budget` | the pay page's JavaScript grew past 110 kB gzipped | Claude moves the new code behind a dynamic import |
| `ERR_PNPM_IGNORED_BUILDS` or a lifecycle-script error | a new dependency wants a build script (`strictDepBuilds`) | Review it, then allow or ignore it in `pnpm-workspace.yaml` with a reason (spec §4.5) |
| npm installs `ethers`, `solc`, `ganache` | `SKIP_DEPENDENCY_INSTALL` missing, so Pages installed the v1 root manifest | Add `SKIP_DEPENDENCY_INSTALL` = `1` |
| The site still shows v1 at `/` | the root directory is still `web` | [§3](#3-change-the-build-settings), step 3 |
