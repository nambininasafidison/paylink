# ADR 0018: The PayPal edition: Ethereum Sepolia, Workers AI, a cut scope, a separate API Worker, and its trust boundaries

- **Status:** accepted
- **Date:** 2026-10-21
- **Deciders:** nambininasafidison (owner), Claude Code (engineering)
- **Related:** [docs/paypal/SPEC.md](../paypal/SPEC.md) (section "Decisions of 2026-10-21" first); research: [sepolia.md](../research/paypal/sepolia.md), [pyusd.md](../research/paypal/pyusd.md), [paypal-tech.md](../research/paypal/paypal-tech.md), [ai-layer.md](../research/paypal/ai-layer.md), [rules.md](../research/paypal/rules.md); ADR 0003 (EIP-3009 nonce bound to the payment); ADR 0004 (immutable contract); ADR 0007 (relayer); ADR 0008 (editions); ADR 0009 (read model); ADR 0013 (deploy page); ADR 0017 (Mezo edition's chain layer, the pattern this follows)

## Context

PayLink Twin is PayLink's entry to the PayPal AI hackathon (deadline 2026-11-12 20:00 UTC; demo live and free until 2026-12-15): one signed PayLink invoice, payable on two rails, PayPal (a twin PayPal invoice) and a dollar stablecoin through the unchanged PayLinkV2 2.0.0, with an AI collections desk that proposes and never moves money. The specification of 2026-10-13 left five choices open or assumed facts that did not hold on 2026-10-21 (**C** read on chain or in a primary file; **S** snippet or the organisers' word; **U** unverified):

- **Chain.** The specification preferred Arbitrum Sepolia with PYUSD, gated. The owner holds Sepolia ETH and 20 test USDC on Ethereum Sepolia (**C**, [sepolia.md](../research/paypal/sepolia.md)) and could not obtain test PYUSD anywhere (faucet.paxos.com geo-blocked from Madagascar; the Google Cloud faucet's transfer ran out of gas; the owner's report). On Sepolia, Circle USDC and Paxos PYUSD both offer EIP-3009 and EIP-2612; PYUSD's `version()` and `eip712Domain()` revert, its `DOMAIN_SEPARATOR()` proves `PayPal USD`/`1`; the CREATE2 factory is there and PayLinkV2's address holds no code (**C**).
- **AI.** The specification assumed the Claude API with a paid key. The owner has none for this event; Cloudflare Workers AI is callable from a Worker through a binding with a free daily allocation of 10,000 neurons (Cloudflare's docs repository at `3fe915d`, **C**; developers.cloudflare.com is unreachable from the build machine).
- **Time.** Feature freeze 2026-10-29, submission about 2026-11-01. The specification's Musts plus its gated items (passkeys, gasless PYUSD) do not fit.
- **Hosting.** The production Pages site serves `/`, `/monad/`, `/base/` and `/mezo/`, which other events are judging; the branch `mezo` is never merged. Cloudflare Pages builds a preview per branch (`https://<branch>.paylink-mg.pages.dev`), and Workers deploy from a committed bundle through Cloudflare's Git integration, as the relayer does (ADR 0007).
- **Network.** From the build machine, npm, GitHub, GitLab, the Sepolia RPC and Mezo's RPC answer; `api-m.sandbox.paypal.com` and developers.cloudflare.com do not. Every PayPal behaviour is therefore built against PayPal's own OpenAPI files (`paypal-rest-api-specifications` at `90e8041`, vendored with their licence) and a fake, and stays **U** until the owner's capture run.
- Devpost confirmed on 2026-10-20 that Madagascar is eligible and that prizes are paid by mail or bank wire, not PayPal (**S**, the owner's Discord thread). Questions on the US sandbox, PYUSD, the AI provider and testing instructions are unanswered.

Questions: which chain and token, which AI provider, what is cut, where the edition and its API run, and what each part is trusted with.

## Options

1. **Chain.** (a) Arbitrum Sepolia with PYUSD (the specification): no test PYUSD in hand, no relayer funding. (b) Base Sepolia with USDC: PayLinkV2 deployed, but Base Sepolia is the Base edition's chain under judging, and PYUSD is absent there (that address holds PAXG, [pyusd.md](../research/paypal/pyusd.md) §1). (c) Ethereum Sepolia: USDC in hand, PYUSD issued there, a new registry entry, PayLinkV2 to deploy.
2. **AI.** (a) Claude API (no key). (b) Workers AI through the `AI` binding, behind a provider interface so a later provider can replace it. (c) No AI (the event is an AI hackathon).
3. **Scope.** (a) Everything the specification marks Must and gated. (b) Cut what the deadline cannot carry and keep the core: the twin, both rails, webhooks, reconciliation, approvals, A1 and A2, the injection suite, the test layers.
4. **Hosting.** (a) Merge into `main`: changes editions under judging. (b) A branch `paypal` whose Pages preview serves `/paypal/`, and a separate API Worker deployed by the owner. (c) Put the API in the relayer: widens the relayer's trust (ADR 0007) and its budget.

## Decision

1. **D-CHAIN: Ethereum Sepolia (11155111)**, option 1(c). RPC `https://ethereum-sepolia-rpc.publicnode.com` (the only one reachable, **C**). USDC `0x1c7D4B196Cb0C7B01d743Fbc6116a902379C7238` is the default and the demo's token; PYUSD `0xCaC524BcA292aaade2DF8A05cC58F0a65B1B3bB9` is listed, supported and shown (rehearsed on a fork), but nobody depends on obtaining it. The registry entry is `disabled` with `editions: ["paypal"]`, so `/`, `/monad/`, `/base/` and `/mezo/` do not offer it; the deploy kit and `tools/verify-deployment` target it as a staged chain. PayLinkV2 is **not deployed** there: the owner deploys it with the kit at `0x448eCce9711860502806A3d5B021a4f9Ba715082`; until its record `protocol/deployments/11155111.json` exists every screen reads "Not deployed" and nothing can be signed or paid (the owner's deployment, recorded on 2026-10-29: transaction `0x9a5ade11…b0e5b3`, block 12,017,054). The SDK accepts PYUSD's domain only because `DOMAIN_SEPARATOR()` proves it (`packages/sdk/src/token-domain.ts`).
2. **D-AI: Workers AI through the `AI` binding**, option 2(b), behind `AiProvider` (`apps/api/src/ai/types.ts`). Primary model `@cf/google/gemma-4-26b-a4b-it`, fallback `@cf/meta/llama-3.3-70b-instruct-fp8-fast`, chosen from the docs repository's model catalog with the reasons and the UNVERIFIED points recorded in `apps/api/src/ai/models.ts`; the daily ceiling is the free 10,000 neurons. The specification's invariants AI-1 to AI-7 stand: the model never signs, never moves money, proposes only what the fence allows, and every flow works without it.
3. **D-SCOPE**, option 3(b). Kept: PayPal operations P1–P11, the webhook with postback signature verification, the reconciler and its echo filter, approvals with HMAC tokens, auto-record with Undo, A1 (message to draft), A2 (read tools and `propose_action` inside the fence), an injection suite of at least 20 cases that blocks, test layers L0–L3, health and Status. Cut: passkeys (EIP-6963 wallets only), the relayer and gasless payments (the payer pays Sepolia gas, by its own EIP-3009 authorisation first, then permit), A3 reason codes, P12 (PayPal's QR code), the judges' PYUSD faucet, and the free-text desk question (the "Check my invoices" key stays).
4. **D-HOST**, option 4(b). The web edition `paypal` is built with the other editions and served at `/paypal/` by the Pages preview of the branch `paypal` (`https://paypal.paylink-mg.pages.dev/paypal/`), under a Content-Security-Policy of its own whose `connect-src` is Sepolia's RPC and the API only. The API is a new Worker, `paylink-api` (`apps/api`: Hono, zod, Durable Objects `Payee` and `Global`, one cron, the `AI` binding, no secret in its configuration), deployed by the owner through Cloudflare's Git integration from its committed bundle `apps/api/deploy/`, with a Node entry over the same app for tests, e2e and an offline demo. Its public contract is `@paylink/api-contract` (types only), which the web edition imports without server code. The PayPal sandbox app is "PayLink Twin"; its client secret exists only as a Cloudflare secret or an environment variable.
5. **Trust boundaries.** The chain is the truth for PayLink payments; PayPal's `GET` of an invoice (P5) is the truth for PayPal payments, and a webhook is a hint that triggers that read. The API is trusted for availability and advice only: it holds no chain key and no wallet client, cannot sign an invoice or a cancellation, and its PayPal client has no operation that captures, refunds or disputes money (`apps/api/src/paypal/client.ts`). The browser shows what is signed and checks what the API says against the signed link (amount, payee, the pinned PayPal host). The model is trusted with nothing: its output is labelled, its numbers checked, its proposals executed only by the deterministic executor after the payee's approval.

## Consequences

- `/`, `/monad/`, `/base/` and `/mezo/` keep their policies byte for byte; their bundles carry the `desk` route's path and label and the optional `api` member of the configuration schema (+27 bytes gzipped on `/monad/pay/`, 109,577 of the 110,000-byte budget, measured 2026-10-21). The branch `paypal`, like `mezo`, is not merged into `main` while other events are judged.
- The payer needs Sepolia ETH for gas: the edition says so and links Circle's faucet for USDC. Without a relayer, a payer's signed authorisation is always submitted by that payer (no relayed path to fall back from).
- The specification's planned ADRs move: this record takes the edition, chain, scope, hosting and trust decisions; the AI fence with approvals and auto-record, and PayPal truth by `GET` with webhooks as hints, get their own records from the workstreams that implement them (*planned (T1)*).
- Everything PayPal answers at run time (statuses after a recorded payment, the `recipient_view_url` host, `reference` search exactness, reminder limits) stays UNVERIFIED in code and documents until the owner's capture run against the sandbox.
- Owner actions this needs: deploy PayLinkV2 on Sepolia with the kit and commit its record; enable the Pages preview for the branch `paypal`; create the Worker `paylink-api` from `apps/api/deploy/` and set its five secrets; create the sandbox app and webhook; run the capture script.
