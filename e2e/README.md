# @paylink/e2e

Playwright end-to-end tests (PAYLINK-V2-SPEC §4.2): the v2 web app (`apps/web`, [ADR 0014](../docs/adr/0014-web-app-and-single-pages-site.md)) as Cloudflare Pages serves it, and the browser deploy page, `web/v2/deploy/` ([ADR 0013](../docs/adr/0013-browser-deploy-page.md)). The T1 flows of §4.2 (relayer, passkeys, indexer) join them with their features.

| Spec | What it proves |
|---|---|
| `specs/deploy.spec.ts` | Monad testnet 10143 (anvil's Monad emulation, 100 gwei base fee, 5 MON): CREATE2 through the proxy installed by its canonical presigned transaction; the one transaction the wallet receives is Deploy.s.sol's, with the clamped gas limit; reads go to the registry RPC; the record equals `tools/verify-deployment`'s; copy and download. Base Sepolia 84532: the wallet does not know the chain and adds it from the registry (proxy via `anvil_setCode`). Arbitrum Sepolia 421614 without the proxy: CREATE at the predicted address, then resume after a reload. Refusals: unknown chain, tampered release data, foreign code at the proxy address, empty wallet, declined signature. Phone (390 px, dark): no horizontal scroll. axe-core WCAG 2.2 AA: zero violations, light and dark |
| `specs/app.spec.ts` | The web app's production build (`apps/web/dist-e2e`, edition `all`, built by the spec) under its real `_headers`, served by `fixtures/pages.ts`, against anvil on 10143 with the PayLinkV2 release at its CREATE2 address and a 6-decimal EIP-2612 + EIP-3009 dollar (`fixtures/app.ts`). Hero flow: the payee signs an invoice (one `eth_signTypedData_v4`, no transaction), shares it (QR code, WhatsApp link); the payer, on another network, sees four lamps, switches network, pays with `payWithPermit` (exactly one transaction, explicit gas limit, exactly the amount moved), gets a receipt that re-verifies on chain; the link then refuses a second payment; the payee's ledger shows it paid, with the total and a CSV export. The armed till stays dark for another invoice and lights for its own. Cancel from the ledger. An impostor contract at the registry address (chain 84532 in this build) turns the genuine lamp red and locks Pay. Refusals: a changed amount, another chain, a wrong memo, trailing data, an oversized link, the payee's own invoice. Framing: blocked by the header, and locked by the JavaScript frame lock when the header is removed. EN → FR → MG. axe-core WCAG 2.2 AA: zero violations on every route, light and dark, 1280 and 390 px, no horizontal scroll at 390 px. No CSP violation under Trusted Types; the service worker installs and the shell opens offline. Each area's headers, and v1 under `/arc/` byte for byte |
| `specs/editions.spec.ts` | The editions (`apps/web/dist-e2e-editions`: `all`, `monad`, `base`, built by the spec) under their real `_headers`, against two anvil chains with the release at its CREATE2 address (10143 with Mock3009 as AUSD and `MockAusdFaucet`; 84532 with Mock3009 as USDC), **the relayer itself** (`apps/relayer` `start:local` in its own process, key derived from anvil's public mnemonic; the production relayer origin of `/config.json` is routed to it) and **Chromium's WebAuthn virtual authenticator with PRF** (`fixtures/editions.ts`). Monad: the seller creates a PayLink key and signs an invoice behind the signing display; the payer, on a phone, creates their own key, gets test AUSD through the relayer's faucet onboarding, pays with one fingerprint through `payWithAuthorization` and never holds MON; the receipt verifies; the armed till lights; the seller cancels another invoice gaslessly (`cancelBySig`); a receive card on Send is paid by a contact for an amount they type. Base: an EOA pays USDC with one EIP-3009 signature and no transaction; a smart account (EIP-5792 `atomic: supported`) pays with "Pay with Base", one `wallet_sendCalls([approve(amount), pay])`. axe-core: zero violations on the pay view and the KeyCard, dark, 390 px |
| `specs/record-parity.spec.ts` | Foundry deploys and writes the record; the page (verify-only, then with the transaction hash) and the CLI print the same bytes |

The deploy page is served from `web/` with the response headers of `web/_headers`; the app from its build with its own `_headers`, by a server that follows Cloudflare Pages' routing and header rules (`fixtures/pages.ts`: the nearest `404.html`, `! Name` detaches, a header set twice is joined with a comma). The registry's RPC URLs are routed to the anvil running that chain id; the mock wallet (`fixtures/wallet.ts`) is announced through EIP-6963 and forwards to anvil, whose default accounts are unlocked. No real key is used.

```bash
source ~/.paylink-toolchain/env.sh                     # sandbox: anvil/forge on PATH, browsers in /opt/pw-browsers
pnpm --filter @paylink/e2e test                         # needs `forge build` in protocol/ (release build for the parity spec, Mock3009 for the app spec)
```

Screenshots of the review and done states (1280 px light, 390 px dark) are written to `e2e/test-results/` (git-ignored).
